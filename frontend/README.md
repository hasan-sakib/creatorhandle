# CreatorHandle — Frontend

Two independent React + Vite applications managed as a Bun workspace:

| App | Directory | Served at | Purpose |
|---|---|---|---|
| creator-workspace | `creator-workspace/` | `/app/` | Authenticated dashboard |
| creator-site | `creator-site/` | `/`, `/@{username}` | Marketing page and public creator profiles |

Both apps are built and served by a single Caddy Docker container. Caddy routes `/app/*` to creator-workspace and everything else to creator-site, and proxies `/api` to the backend.

## Requirements

- [Bun](https://bun.sh/) 1.4. `frontend/` is the Bun workspace root (`package.json`, `bun.lock`, `node_modules/`); run `bun` commands here, `make` commands from the repo root.

## Quick Start

```bash
cd frontend && bun install   # installs every workspace package (or `make setup`)
make up                    # backend, db, storage and the built frontend on :5173
docker compose stop frontend
make dev-workspace         # dashboard dev server: http://localhost:5173/app/
make dev-site              # or the public site:   http://localhost:5173/
```

The dev servers read `VITE_API_URL` (default `http://localhost:8000`) from the
repo-root `.env` (`envDir` in each `vite.config.ts`).

## Authentication

The workspace uses JWT stored in `localStorage` under `access_token`. Two login methods:

**Email + password:**
```tsx
loginMutation.mutate({ username: email, password })
```

**Google Sign-In (implicit flow):**
```tsx
const triggerGoogleLogin = useGoogleLogin({
  onSuccess: async (tokenResponse) => {
    const res = await LoginService.loginWithGoogle({ body: { token: tokenResponse.access_token } })
    localStorage.setItem("access_token", res.access_token)
    navigate({ to: "/" })
  },
})
```

`GoogleOAuthProvider` wraps the entire app in `main.tsx`. Requires `VITE_GOOGLE_CLIENT_ID` to be set at build time.

## Cross-App Navigation

creator-workspace runs at basepath `/app`. Links that navigate between the two apps (e.g. from creator-site to the login page) must use plain `<a>` tags, not TanStack Router `<Link>`:

```tsx
// Correct
<a href="/app/login">Log in</a>

// Wrong — resolves inside creator-site
<Link to="/login">Log in</Link>
```

## Building for Docker

Both apps are built into one Caddy image (`frontend/Dockerfile`). `VITE_API_URL`
(empty in production, where `/api` is same-origin) and `VITE_GOOGLE_CLIENT_ID`
are build args baked into the bundles; after changing them:

```bash
docker compose build frontend && docker compose up -d frontend
```

## Caddy Routing

`frontend/Caddyfile` — path-based routing in the single Caddy container:

```
/api, /docs, /redoc  → reverse_proxy backend:8000
/media/*             → uploaded images, read-only from RustFS
/app/*               → creator-workspace dist (index.html fallback)
/*                   → creator-site dist      (index.html fallback)
/assets/*            → cached immutably; a missing asset is a 404, not index.html
/login, /signup, …   → redirected to /app/… (old dashboard paths)
```

## Regenerating the API Clients

```bash
make client     # = bash frontend/scripts/generate-client.sh; the backend does not need to run
```

This regenerates `creator-workspace/src/client` (whole API) and
`creator-site/src/client` (public endpoints only). Commit both; CI fails if
they are stale.

## E2E Tests (Playwright)

```bash
make up          # tests run against http://localhost:5173
make test-e2e    # or, in creator-workspace: bun run test:e2e / test:e2e:ui
```

Tests create their own users through the dev API; they need `FIRST_SUPERUSER`
and `FIRST_SUPERUSER_PASSWORD` from the root `.env`.

## Lint, format, type-check

```bash
# in frontend/
bun run lint:ci     # biome ci, every package
bun run lint        # biome check --write (applies fixes)
bun run typecheck   # tsc --noEmit, every package
bun run build       # both apps
```
